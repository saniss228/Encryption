# 🔐 Encryption — защищённый мессенджер с двойным шифрованием

**Версия 3.3.0.** Три клиента — **сайт**, **приложение для ПК** и **приложение для Android** —
на одном сервере с одним и тем же криптографическим ядром. Каждое сообщение шифруется
**дважды**, файлы живут **ровно 24 часа** и **навсегда удаляются с сервера сразу после
скачивания получателем** (в интерфейсе — метка **«Только локально / Local only»**),
интерфейс переведён на **4 языка**, на устройство — **один аккаунт**, а за порядок
отвечает **админ-панель** (аккаунт `saness`): блокировки, группы, файлы, журнал,
рассылка объявлений. При этом администратор **не может читать переписку** — она остаётся
зашифрованной на устройствах.

```
Сообщение ──► AES-256-GCM (случайный ключ сообщения)             ← слой 1
          ──► RSA-4096-OAEP-SHA256 (ключ на каждого получателя)  ← слой 2
          ──► ECDH P-256 + HKDF + AES-GCM (forward secrecy)      ← слой 3
          ──► ECDSA P-256 (подпись конверта, защита от подмены)
                          │
                          ▼
        сервер видит только шифротекст  { l1, wrap, sig }
```

### Что нового в 3.3.0

* **Все клиенты перешли на порт 3000.** Сервер, сайт, приложение для ПК и Android
  теперь работают на одном порту — **3000**. Отдельный «порт для браузера» (8080)
  больше не нужен: порт 3000 браузеры не блокируют, поэтому и сайт, и приложения
  ходят по одному и тому же адресу. Приложения пересобраны — порт зашит в них.
* **Адрес, сохранённый в приложении до обновления** (`…:6000` или `…:8080`),
  автоматически переводится на `…:3000` — вход не сломается.
* **Адрес официального сервера** в клиентах — `http://45.90.45.92:3000`.
* Своих адресов это не касается: в «Настройках → Сервер» можно указать любой,
  например `http://192.168.1.10:3000` — тот, что показывает окно запуска.

### Что нового в 3.2.3

* **Правильный адрес для телефона.** Раньше в окне запуска показывался адрес
  первого попавшегося адаптера — им оказывался Radmin VPN или «хот-спот» Windows
  (`192.168.137.1`), и телефон по нему не подключался. Теперь адрес берётся с
  настоящего Wi-Fi/Ethernet-адаптера, а виртуальные (VPN, Hyper-V, WSL, хот-спот)
  показываются отдельным списком — с пометкой, что для телефона они не подходят.
  Свой адрес можно задать вручную: `START-ENCRYPTION-WINDOWS.cmd 3000 192.168.1.50`.
* **Администратор по умолчанию — `saness`** (было `saniss`). Прежний логин можно
  сохранить: в настройках службы укажите `ENC_ADMINS=saniss,saness`.
* Шифрование, форматы и API не изменились — версии совместимы.

### Что нового в 3.2.2

* **Подключение снова работает: сервер слушает порт 6000.** Скрипты запуска
  поднимали сервер на 8080 «по умолчанию», а приложения (ПК и Android) и сайт на
  сервере проекта настроены на 6000 — из-за этого приложение не могло подключиться.
  Теперь запуск всегда на 6000, как и было задумано.
* **Сайт на этом же компьютере открывается на 8080.** Браузеры блокируют порт
  6000 (`ERR_UNSAFE_PORT`), поэтому сервер слушает оба порта одним процессом:
  6000 — для приложений и API, 8080 — для браузера. Данные и аккаунты общие.
* **Если открыть `localhost:6000`, порт меняется на 8080 автоматически** — сайт
  откроется без ручной правки адреса.
* Подсказки при выборе своего сервера обновлены (примеры с портом 6000) на всех
  четырёх языках. Шифрование, форматы и API не изменились — версии совместимы.

### Что нового в 3.2.1

* **Запуск на Windows стал надёжным.** Сервер больше не запускается «заданием»
  PowerShell: раньше каждая строка его журнала в PowerShell 5.1 превращалась
  в ошибку (`NativeCommandError`), и скрипт падал, останавливая сервер сразу
  после старта. Теперь сервер — отдельный процесс, его журнал пишется в файл
  `data\server-error.log` и показывается в окне по мере появления.
* Если сервер не поднялся или упал, скрипт показывает последние строки журнала
  и не закрывает окно сам — причину видно сразу.

### Что нового в 3.2.0

* **Выбор сервера при входе**: «Официальные серверы» (список) или «Свой сервер»
  (ввод адреса) — с проверкой связи и запоминанием выбора на устройстве.
  Раздел «Настройки → Сервер» меняет адрес и на уже настроенном приложении.
* **Перенос данных на другой сервер**: «Настройки → Админ-панель → Данные и перенос →
  Скачать копию данных». Один файл `*.encbak` содержит базу, файлы, медиа и ключи;
  он зашифрован вашим паролем (AES-256-GCM, PBKDF2-SHA512 ×300 000).
  Развёртывание на новом сервере — `python3 tools/migrate_server.py import файл.encbak --force`.
* **Запуск на Windows без ошибок**: скрипт `ЗАПУСТИТЬ-МЕССЕНДЖЕР-WINDOWS.cmd` больше не
  падает на журнале сервера в PowerShell 5.1.
* Шифрование, форматы и API не изменились — версии совместимы.

Ваш белый IP прописан по умолчанию во всех клиентах: `http://45.90.45.92:3000`.
Через nginx на 80/443 сайт доступен и как `http://45.90.45.92/`.

**Один порт для всего — 3000.** Локальный запуск скриптом поднимает сервер на

## Быстрый старт

### 1. Сервер (на машине с белым IP 45.90.45.92)

```bash
sudo bash deploy/install.sh
```

Скрипт поставит Python, nginx, systemd-службу и откроет порты. Проверка:

```bash
curl -s http://127.0.0.1:3000/api/v1/health   # {"status":"ok","version":"3.3.0",...}
```

Откройте `http://45.90.45.92/` — это сайт с мессенджером.

> Сайт отдаётся nginx (80/443), сам сервер слушает **3000**. Тот же порт открыт
> и наружу: приложения (EXE/APK) подключаются к `http://45.90.45.92:3000`
> напрямую, а адрес при необходимости меняется в «Настройки → Сервер».
> Порт 3000 браузеры не блокируют — `ERR_UNSAFE_PORT` здесь невозможен.

### 2. Локальный запуск (для проверки без сервера)

```bash
python3 -m venv .venv && .venv/bin/pip install -r server/requirements.txt
ENC_PORT=3000 .venv/bin/python -m server.app     # сайт и API на порту 3000
# откройте http://127.0.0.1:3000 — это сайт; здесь же демо-режим без сервера
```

Демо-режим работает вообще без сервера: сервер эмулируется в браузере, но шифрование
**настоящее** — конверты строит то же ядро `web/js/crypto.js`.

### 3. Проверка, что всё работает

```bash
bash tools/run_tests.sh                                  # крипто + API
PUPPETEER_DIR=/tmp/ui bash tools/run_tests.sh            # + UI в headless-браузере
```

Тесты проверяют: оба слоя шифрования и их независимость, проверку подписи, фразу
восстановления, шифрование файлов, «один аккаунт на устройство», доставку между
двумя устройствами по WebSocket, **удаление файла с сервера после скачивания**
(метка «только локально», `410 LOCAL_ONLY` при повторной попытке), переключение
языков интерфейса, то, что **в конверте на сервере нет открытого текста**, и работу
**админ-панели**: права `saness`, закрытый для обычных пользователей доступ,
блокировку/разблокировку, принудительный выход, рассылку объявлений, закрытие
регистрации, уборку файлов, локализации панели и запись действий в журнал.

## Функции

Подробный разбор — в [`docs/FEATURES.md`](docs/FEATURES.md). Коротко:

* **Шифрование:** двойное (AES-256-GCM + RSA-4096-OAEP) + третий канал ECDH для forward
  secrecy, подпись ECDSA каждого конверта, шифрование имён файлов, пароль не покидает устройство
  (PBKDF2-SHA512 ×310 000 + Argon2id на сервере).
* **Сообщения:** личные и групповые чаты до 200 участников, ответы, пересылка, реакции,
  редактирование (48 ч), удаление у всех, закрепления, черновики, архив, «Избранное»,
  самоуничтожение по таймеру и «прочитал — исчезло».
* **Файлы:** шифруются на устройстве по чанкам 1 МБ, живут **ровно 24 часа**, имена тоже
  зашифрованы. Как только получатель скачал файл (и расшифровал его на устройстве),
  сервер **удаляет свою копию безвозвратно** — остаётся только «надгробие» без данных,
  а в интерфейсе появляется метка **«🔒 Только локально / Local only»** у отправителя
  и получателя (второй может увидеть её даже при повторной попытке скачивания: `410 LOCAL_ONLY`).
  Подробности — [`docs/API.md`](docs/API.md#7-файлы-24-часа-и-только-локально).
* **Связь:** текст, фото, видео, документы, голосовые, аудио- и видеозвонки (WebRTC
  DTLS-SRTP), демонстрация экрана, статусы, «печатает…», квитанции ✓/✓✓.
* **Аккаунт:** **один аккаунт на устройство** (жёсткая привязка + карантин 30 дней при
  смене), до 4 устройств на аккаунт, список сессий с отзывом, вход по коду с доверенного
  устройства, шифрованный бэкап ключей, «тревожная кнопка», журнал безопасности.
* **Забыли пароль:** 24-словная фраза восстановления / код с уже вошедшего устройства /
  новый аккаунт после освобождения устройства — [`docs/RECOVERY.md`](docs/RECOVERY.md).
* **Оформление:** тёмная и светлая тема, адаптив под телефон и ПК, drag&drop файлов,
  горячие клавиши, локальный полнотекстовый поиск (сервер текст не видит).
* **Языки:** русский, английский, испанский, немецкий — переключаются в
  «Настройки → Приложение → Язык» и в окне входа; по умолчанию язык берётся из системы.
* **Только нужный текст:** в интерфейсе нет адресов сервера, портов и версий бэкенда —
  статус соединения показывается как «Защищённое соединение».
* **Админ-панель (аккаунт `saness`):** обзор сервера, пользователи (поиск, блокировка с
  причиной, выход со всех устройств, админ-права, удаление), группы, файлы, журнал
  безопасности, рассылка объявлений и настройки (в том числе закрытая регистрация).
  Переписку администратор прочитать **не может** — в панели только метаданные,
  содержимое зашифровано на устройствах. Подробности — [`docs/API.md`](docs/API.md).


## Перенос данных на свой сервер

Администратор сервера (или владелец) может перевезти всё на другую машину:

```bash
# на старом сервере: копия всех данных в один зашифрованный файл
python3 tools/migrate_server.py export --out encryption-backup.encbak

# на новом сервере: проверка и развёртывание (сервер остановлен)
python3 tools/migrate_server.py verify encryption-backup.encbak
python3 tools/migrate_server.py import encryption-backup.encbak --force
```

То же самое из интерфейса: **Настройки → Админ-панель → Данные и перенос →
Скачать копию данных** (пароль к копии задаётся там же).

Важно про шифрование: содержимое переписки и файлов в копии остаётся закрытым
ключами устройств — сервер их не знает и прочитать не может никто, включая
администратора. Пароль к файлу копии восстановить нельзя, храните его отдельно.

## Запуск одной командой

* **Windows** — распакуйте архив и дважды щёлкните `ЗАПУСТИТЬ-МЕССЕНДЖЕР-WINDOWS.cmd`
  (рядом — `START-ENCRYPTION-WINDOWS.cmd`, то же самое латиницей). Скрипт сам создаст
  окружение, поставит зависимости, поднимет сервер, дождётся готовности и откроет
  сайт в браузере. Порт — `3000` (и сайт, и приложения); свой порт задаётся
  аргументом: `START-ENCRYPTION-WINDOWS.cmd 9000`, адрес для телефона — вторым:
  `START-ENCRYPTION-WINDOWS.cmd 3000 192.168.1.50`.
* **Linux / macOS** — `bash tools/start-server.sh` (или `bash tools/start-server.sh 9000`).

Полезные ключи PowerShell-скрипта (`tools/start-encryption.ps1`): `-Port` (по умолчанию
3000), `-LanIp` (адрес для телефона вручную), `-BindHost`, `-NoBrowser`
(не открывать браузер), `-NoInstall` (не ставить зависимости), `-Reinstall`
(пересобрать окружение).
