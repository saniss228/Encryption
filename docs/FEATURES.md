# Encryption — что входит в хороший мессенджер

Полный перечень функций, по которым оценивают современные защищённые мессенджеры
(Telegram, WhatsApp, Signal, Threema, Element). Столбец «Статус» — состояние в
проекте Encryption: ✅ реализовано, 🟡 базово, ⏳ план.

## 2. Шифрование и приватность (главное отличие)
| Функция | Статус | Как сделано |
|---|---|---|
| **Двойное шифрование каждого сообщения** | ✅ | слой 1: AES-256-GCM (случайный ключ сообщения); слой 2: RSA-4096-OAEP-SHA256-обёртка ключа для каждого получателя |
| Третий, независимый канал ключа (FS) | ✅ | ECDH P-256 + HKDF-SHA256 + AES-256-GCM на эфемерном ключе |
| Подпись конверта | ✅ | ECDSA P-256 — защита от подмены и MITM |
| E2E по умолчанию | ✅ | сервер физически не имеет приватных ключей |
| Forward secrecy при потере RSA-ключа | ✅ | сообщение расшифровывается вторым слоем, даже если RSA-ключ скомпрометирован |
| Zero-knowledge сервер | ✅ | хранит только конверт `{l1, wrap, sig}` |
| Шифрование файлов на устройстве | ✅ | AES-256-GCM по чанкам, ключ файла — в двухслойной обёртке |
| Шифрование имён файлов | ✅ | `name_enc` |
| Пароль не уходит на сервер | ✅ | PBKDF2-SHA512 ×310 000 на устройстве + Argon2id на сервере |
| Бэкап ключей в облаке (зашифрованный) | ✅ | AES-256-GCM под паролем/фразой; сервер не может открыть |
| Самоуничтожающиеся сообщения | ✅ | таймер в чате + burn-after-read (удаление через 5 с после прочтения) |
| Срок жизни файлов ровно 24 часа | ✅ | жёсткий TTL, автоуборка каждые 5 минут |
| Проверка ключа собеседника (отпечаток) | ✅ | SHA-подобный отпечаток + отметка «доверенный контакт» |
| Блокировка пользователей | ✅ | `contacts.blocked` |
| Скриншоты в Android (FLAG_SECURE) | ⏳ | включается одной строкой, отключено для удобства демо |
| Двухфакторный вход (пароль + код) | 🟡 | вход по 2 независимым факторам: пароль и код с доверенного устройства |

## Что сознательно НЕ делается
* **Сервер не хранит ключи и не может читать переписку** — поэтому «сброс пароля админом с доступом к истории» принципиально невозможен.
* **Нет облачного хранения истории на сервере дольше нужного** — история живёт на устройствах; на сервере только то, что нужно для доставки.
* **Нет «тихого» бэкдора**: подпись каждого конверта проверяется на клиенте.

## Порядок разработки (что делать дальше)
1. Домен + Let's Encrypt → HTTPS/WSS по умолчанию.
2. TURN-сервер (coturn) → звонки работают за любым NAT; групповые звонки через SFU (mediasoup/Janus).
3. Push-уведомления: FCM для Android, APNs для iOS.
4. Регистрация по SMS-коду (провайдер) и вход по QR между устройствами «в один тап».
5. Полноценные треды и опросы в UI; папки чатов; экспорт чата в зашифрованный архив.
6. Многоустройственная синхронизация истории через зашифрованный «ящик» сообщений (как в Signal Desktop).
