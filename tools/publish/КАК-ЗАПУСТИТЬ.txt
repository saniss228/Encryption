 ОТПРАВКА ENCRYPTION 3.1.0 В GITHUB — одна кнопка
════════════════════════════════════════════════════════════════════════

Репозиторий: https://github.com/saniss228/Encryption
Результат:   ветка main получает версию 3.1.0 целиком + тег v3.1.0.
             Ваша прежняя история сохраняется — это обычное дополнение,
             ничего не стирается (обновление без force).

────────────────────────────────────────────────────────────────────────
 ЧТО НУЖНО ОДИН РАЗ ПОЛУЧИТЬ: ТОКЕН GITHUB
────────────────────────────────────────────────────────────────────────
  1. Откройте https://github.com/settings/tokens?type=beta
     (Settings → Developer settings → Personal access tokens → Fine-grained tokens)
  2. «Generate new token»:
       Token name:  encryption-publish
       Expiration:  7 дней (после отправки токен можно удалить)
       Repository access: Only select repositories → Encryption
       Permissions → Repository permissions → Contents: Read and write
  3. «Generate token» и скопируйте строку (начинается с github_pat_…).

  Скрипт спросит этот токен при запуске и нигде его не сохранит.
  Если у вас уже настроен вход в GitHub (GitHub Desktop, менеджер учётных
  данных Windows, SSH-ключ) — токен можно не вводить: просто нажмите Enter,
  скрипт отправит через git вашими учётными данными.


════════════════════════════════════════════════════════════════════════
 WINDOWS
════════════════════════════════════════════════════════════════════════
  1. Распакуйте этот архив в отдельную папку (например, C:\encryption-publish).
  2. Двойной клик по «ЗАПУСТИТЬ-WINDOWS.cmd».
  3. Вставьте токен (правый клик в окне — «Вставить»), нажмите Enter.
  4. Дождитесь строки «ГОТОВО».

  Если Windows предупредит о запуске скрипта — разрешите (файлы не подписаны,
  потому что собраны локально). Можно запустить вручную:

      powershell -ExecutionPolicy Bypass -File "C:\encryption-publish\publish-to-github.ps1"

  Git для Windows устанавливать НЕ обязательно: если его нет, скрипт
  отправит файлы напрямую через GitHub API (работает на любом Windows 10/11).

  Полезные варианты:

      powershell -File publish-to-github.ps1 -Token github_pat_xxx
      powershell -File publish-to-github.ps1 -ApiOnly            # без git
      powershell -File publish-to-github.ps1 -Release            # ещё и релиз создать


════════════════════════════════════════════════════════════════════════
 LINUX / macOS
════════════════════════════════════════════════════════════════════════
  1. Распакуйте архив:   unzip ОТПРАВИТЬ-НА-GITHUB.zip && cd ОТПРАВИТЬ-НА-GITHUB
  2. Запустите:          bash publish-to-github.sh
  3. Вставьте токен (ввод скрыт), нажмите Enter.

  Если установлен git — отправит готовую историю из бандла; если нет —
  загрузит файлы через GitHub API (нужен python3, он есть в Linux и в macOS
  с инструментами разработчика).

  Варианты:   bash publish-to-github.sh --token ghp_xxx
              bash publish-to-github.sh --api-only


════════════════════════════════════════════════════════════════════════
 ЧТО ЛЕЖИТ В АРХИВЕ
════════════════════════════════════════════════════════════════════════
  ЗАПУСТИТЬ-WINDOWS.cmd            — двойной клик (Windows)
  publish-to-github.ps1            — скрипт для Windows (git или API)
  publish-to-github.sh             — скрипт для Linux/macOS (git или API)
  github_upload.py                 — выгрузка через API без git (нужен python3)
  encryption-3.1.0-github.bundle   — вся история проекта в одном файле (4,4 МБ)
  files/                           — файлы версии 3.1.0 (то, что попадёт в репозиторий)

  Тяжёлые сборки (EXE, APK, архивы) в репозиторий не отправляются — так
  правильно: они собираются командами tools/build_release.sh и tools/build_apk.sh.
  Сами сборки лежат в release/encryption-3.1.0-all.zip.

 ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
════════════════════════════════════════════════════════════════════════
  «Bad credentials» или 401
      Токен скопирован не полностью либо истёк — создайте новый.
  «Resource not accessible by personal access token» / 403
      У токена нет права Contents: Read and write на этот репозиторий.
  «could not read Username for 'https://github.com'»
      Git не знает вашего входа — введите токен в ответ на запрос скрипта.
  «failed to push some refs» / non-fast-forward
      Ветка main на GitHub изменилась после 0586329. Скрипт сам это увидит
      и отправит файлы вторым способом (через API) — он всегда дополняет
      текущую ветку, ничего не перезаписывая.
  Отправка повторится без вреда
      Скрипт умеет продолжать: уже загруженные файлы повторно не отправляются,
      коммит просто допишется поверх текущего main.

  Проверить результат: https://github.com/saniss228/Encryption
  После отправки токен можно удалить на той же странице настроек.
